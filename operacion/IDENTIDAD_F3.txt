TABLAS Y PROCESOS
Seguridad: users.auth_version, auth_sessions, auth_mutex, historial EF.
Laravel: external_identities y identity_revocations. Estado pendiente es durable.
Los cuatro MS comprueban la autoridad en cada operación; no hay caché de permisos
que deba vaciarse manualmente para aplicar una revocación.
No se añadieron jobs de negocio ni credenciales técnicas. ServiceIdentityProvider
rechaza hasta existir un caso de uso autorizado en fases posteriores.
Laravel programa identity:retry-revocations cada minuto SOLO en modo remoto.
En una activación preparada, conservar cron schedule:run cada minuto con usuario
y rutas del despliegue. Ejecutar identity:retry-revocations para intervención manual.
Conservar las colas/tareas Laravel existentes; los espejos antiguos siguen apagados.
Supervisar cantidad de identity_revocations con confirmed_at NULL y expires_at
futura. Un retorno CLI 0 no significa que un registro con backoff futuro ya se haya
confirmado. Credencial se borra al confirmar y registro se purga al vencer.
No borrar pendientes para ocultar una caída. Dar alarma si crecen o se retrasan.

DIAGNÓSTICO SIN SECRETOS
Laravel identity.request: servicio, método/ruta sin ID, estado, duration_ms y UUID
correlation_id; omite cuerpos y Authorization. Consumidores registran solo tipo
de fallo de la comprobación; no incorporan mensaje/cuerpo HTTP remoto al log.
401: autenticar nuevamente; 403: revisar permisos activos; 503: comprobar autoridad
antes de volver a operar. Logout pendiente NO confirma cierre global.
No repetir automáticamente password/perfil tras timeout; consultar estado primero.
Mantener APP_DEBUG=false en despliegues. Revisar retención/ACL de logs/trazas.

RECUPERACIÓN POR MODO
Preferir rollback del par código/configuración COMPATIBLE conservando las tablas
aditivas. No reactivar el JwtGuard anterior ni espejos como método de recuperación.
No alternar remote->local sobre la misma instancia para aparentar continuidad.
Local y remoto tienen datos distintos; no existe réplica automática de negocio.
Down de Seguridad se ensayó solo en copia sintética: conserva identidades pero
quita sesiones/versiones; no usarlo como recuperación ordinaria de producción.
Down de Laravel quitaría mapas/denegaciones; conservarlos hasta un retiro planificado.
MySQL DDL puede quedar parcialmente aplicado si se interrumpe: inspeccionar columnas,
índices e historial EF antes de reintentar; recuperar sobre copia y respaldo probado.

Si se restaura un snapshot antiguo, puede contener sesiones antes revocadas.
Antes de exponerlo, ROTAR la clave de firma compartida en autoridad, consumidores
y Laravel, cerrar la ventana legacy y exigir nuevo login. No restaurar la clave
antigua como solución. Verificación ensayada: token del snapshot falla con clave nueva.
Para recuperación Sanctum, revocar personal_access_tokens de la copia restaurada
antes de abrirla; conservar hashes de usuarios. Probar aislamiento de otros dominios.
Rotar APP_KEY exige tratar credenciales cifradas pendientes: confirmar previamente,
o rotar primero la clave JWT de forma coordinada para invalidar accesos anteriores.
No descartar silenciosamente el cifrado y anunciar cierres correctos.

REPETIR LAS PRUEBAS (POWERSHELL)
Desde backend: .\scripts\test-isolated.ps1
Integral: .\scripts\test-isolated.ps1 -Integration -BrowserTests
Requisitos integral: SQL Server localhost/integrated disponible, .NET SDK10,
runtime privado ASP.NET8 y Chromium Playwright. El runner arranca MySQL en puerto
aleatorio, usa nombres exclusivos y detiene solo procesos propios.
En cada carpeta .NET: dotnet test tests/<Proyecto.Tests>/<Proyecto.Tests>.csproj
Comercial/Finanzas: MULTILIDER_SQLSERVER_TESTS=1 para no omitir pruebas SQLServer.
Frontend y worktree: npm run test:session; npm run build.
Preparar navegador: PLAYWRIGHT_BROWSERS_PATH=<frontend>/.phase3/browsers;
node node_modules/@playwright/test/cli.js install chromium.
El worktree necesita dependencias npm compatibles propias o una unión local node_modules;
esta unión no se publica ni forma parte del repositorio.

Runtime8 de pruebas: descargar metadatos oficiales
https://builds.dotnet.microsoft.com/dotnet/release-metadata/8.0/releases.json
Elegir aspnetcore-runtime-win-x64.zip de la versión 8.0.33, descargar por su URL,
comparar Get-FileHash -Algorithm SHA512 con hash del mismo elemento y extraer en
multilider-ms-seguridad/.artifacts/runtime8. Ejecutar allí dotnet --list-runtimes.
No sustituye ni actualiza la instalación global. Revisar soporte/parches y la
migración de versiones principales antes del despliegue F9.
